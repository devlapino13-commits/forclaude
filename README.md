# forclaude

Инструменты для работы с базой данных Firebird (кредитная организация):
выгрузка структуры (метаданных) и образца данных для последующего анализа.

Основной способ — **чистые SQL-скрипты для IBExpert** (папка `sql/`), без
установки Python и внешних зависимостей.

## Как пользоваться (IBExpert)

Откройте SQL-редактор в IBExpert, подключившись к нужной базе, и по очереди
выполняйте скрипты из папки `sql/`. Каждый скрипт — это либо обычный
`SELECT`, либо `EXECUTE BLOCK` (анонимный PSQL-блок), который **ничего не
создаёт и не меняет в базе** — только читает.

Результат каждого запроса — грид. Экспортируйте его в файл через IBExpert:
правой кнопкой по результату → **Export Data** / **Grid to file** (или
аналогичный пункт меню в вашей версии) → сохраните как CSV/Excel/текст.

| Скрипт | Что делает |
|---|---|
| `sql/01_metadata_columns.sql` | Все таблицы/представления: колонки, типы, `NOT NULL`, PK, значение по умолчанию |
| `sql/02_metadata_foreign_keys.sql` | Внешние ключи (какая таблица.колонка → на какую таблицу.колонку ссылается) |
| `sql/03_metadata_indexes.sql` | Индексы всех таблиц |
| `sql/04_source_views_procedures_triggers.sql` | Исходники представлений, хранимых процедур и триггеров (3 отдельных запроса — там часто бизнес-логика) |
| `sql/05_export_data_sample.sql` | Данные: до **100 самых свежих строк** с каждой таблицы |

Присылайте мне результаты этих запросов (файлы или просто текст) — по ним я
пойму структуру базы и смогу решать задачи по ТЗ.

## `sql/05_export_data_sample.sql` — подробнее

Это самый нетривиальный скрипт: он в одном `EXECUTE BLOCK` обходит все
пользовательские таблицы и для каждой строит и выполняет динамический
`SELECT`, беря **не более 100 строк**, при этом старается взять именно
**свежие** записи:

1. если в таблице есть колонка типа `DATE`/`TIMESTAMP` — сортировка по ней
   `DESC` (среди нескольких таких колонок в приоритете «дата
   изменения/обновления», затем «дата создания», затем любая другая
   дата/время);
2. если такой колонки нет — сортировка по первому полю первичного ключа
   `DESC` (эвристика: обычно это автоинкремент, и большие значения —
   более новые записи);
3. если нет ни того, ни другого — строки берутся без сортировки
   (свежесть в этом случае не гарантирована).

Результат — плоская таблица из 3 колонок:

- `TABLE_NAME` — имя таблицы;
- `ROW_TYPE` — `HEADER` (первая строка = имена колонок), `SORTBY`
  (по какой колонке и почему отсортировано) или `DATA` (сама запись);
- `ROW_TEXT` — содержимое строки, поля разделены символом `|`.

Настройки в начале блока (`MAXROWS`, `DO_MASK`) можно менять прямо в
тексте скрипта перед запуском.

### ⚠️ Важно: чувствительные данные

База принадлежит кредитной организации и почти наверняка содержит
персональные и финансовые данные (ФИО, паспортные данные, номера
счетов/карт, суммы и т.п.). Поэтому:

1. В `sql/05_export_data_sample.sql` по умолчанию включена маскировка
   (`DO_MASK = 1`) — значения в колонках с «подозрительными» именами
   (паспорт, карта, ИНН, телефон, email, адрес, ФИО, зарплата, баланс и
   т.п.) заменяются на `*** MASKED ***`. Список ключевых слов — прямо в
   тексте скрипта, при необходимости дополните под вашу схему.
2. Перед передачей выгрузки куда-либо (в том числе в чат с ИИ) —
   просмотрите результат самостоятельно: маскировка по имени колонки не
   гарантирует, что не останутся чувствительные данные в полях с
   нетипичными именами.
3. По возможности используйте тестовый/обезличенный контур, а не
   продуктивную базу.

## Альтернатива: `export_firebird.py` (Python)

В репозитории также есть Python-скрипт с аналогичной логикой (для случаев,
когда есть возможность запускать Python и требуется более гибкая
автоматизация — например, регулярные выгрузки). Для работы в IBExpert он
не нужен — используйте SQL-скрипты выше. Подробности — в комментариях
самого файла `export_firebird.py`.
