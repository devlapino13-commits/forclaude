# forclaude

Инструменты для работы с базой данных Firebird: выгрузка структуры (метаданных)
и образца данных для последующего анализа.

## Выгрузка структуры и данных Firebird (`export_firebird.py`)

Скрипт подключается к базе Firebird и выгружает:

- список таблиц и представлений, колонки, типы, `NOT NULL`, значения по
  умолчанию;
- первичные и внешние ключи, индексы;
- исходники представлений (`views.sql`), хранимых процедур
  (`procedures.sql`) и триггеров (`triggers.sql`) — там часто зашита
  бизнес-логика, полезная для понимания базы;
- данные каждой таблицы — **не более 1000 строк** (настраивается).

Результат сохраняется в папку и упаковывается в один `.zip`.

### Установка

```bash
pip install -r requirements.txt
```

Требуется установленный клиент Firebird (клиентская библиотека `fbclient`)
на машине, где запускается скрипт — обычно она уже есть, если на машине
стоит сервер или клиент Firebird.

### Запуск

```bash
python export_firebird.py \
    --database /path/to/database.fdb \
    --host 127.0.0.1 \
    --user SYSDBA \
    --output export_result \
    --mask
```

Пароль лучше не указывать в командной строке (останется в истории shell), а
задать через переменную окружения или ввести по запросу:

```bash
export FB_PASSWORD=masterkey
python export_firebird.py --database /path/to/database.fdb --user SYSDBA --host 127.0.0.1
```

Если база — локальный файл на этой же машине (embedded/без сетевого
сервера), `--host` не указывается:

```bash
python export_firebird.py --database /path/to/database.fdb --user SYSDBA
```

### Полезные флаги

| Флаг | Назначение |
|---|---|
| `--max-rows N` | сколько строк на таблицу выгружать (по умолчанию 1000) |
| `--tables T1 T2 ...` | выгрузить данные только по указанным таблицам (метаданные — всегда по всем) |
| `--no-data` | выгрузить только метаданные, без данных |
| `--count-rows` | посчитать точное число строк в каждой таблице (может быть медленно на больших таблицах) |
| `--mask` | маскировать значения в колонках с чувствительными именами (паспорт, карта, ИНН, телефон, email, адрес и т.п.) |
| `--charset` | кодировка соединения, по умолчанию `UTF8`; если видите "кракозябры" — попробуйте `WIN1251` |
| `--no-zip` | не паковать результат в zip, оставить папкой |

### ⚠️ Важно: чувствительные данные

База принадлежит кредитной организации и почти наверняка содержит
персональные и финансовые данные (ФИО, паспортные данные, номера
счетов/карт, суммы и т.п.). Рекомендуется:

1. Запускать с флагом `--mask` — он маскирует значения в колонках, чьи
   имена похожи на чувствительные (см. список `SENSITIVE_NAME_PATTERNS` в
   скрипте — при необходимости дополните его под конкретную схему БД).
2. Перед передачей файла куда-либо (в том числе в чат с ИИ) — просмотреть
   содержимое `data/*.csv` самостоятельно: маскировка по имени колонки не
   гарантирует, что не останется чувствительных данных в других полях
   (например, в комментариях, BLOB-полях, полях с нетипичными именами).
3. При возможности выгружать данные с тестового/обезличенного контура, а
   не с продуктивной базы.

### Формат результата

```
export_result/
├── metadata.md          # таблицы, колонки, типы, PK/FK, индексы
├── views.sql            # исходники представлений
├── procedures.sql       # исходники хранимых процедур
├── triggers.sql         # исходники триггеров
├── row_counts.txt       # точное число строк (только если указан --count-rows)
└── data/
    ├── TABLE1.csv        # до 1000 строк, разделитель ";"
    ├── TABLE2.csv
    └── ...
```

Всё это упаковывается в `export_result.zip` — этот файл и нужно прислать
для анализа структуры базы.
