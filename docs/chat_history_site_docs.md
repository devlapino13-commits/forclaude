## Часть 1. Основная сессия — с нуля до полноценного сайта

### 1.1. Исходные данные и пивот к статическому сайту
- Источник: `Метаданные БД\Result.html` (536 тыс. строк, IBExpert-экспорт): 1552 таблицы, 302 функции, 5164 индекса, 2520 FK, 68 CHECK.
- Изначально шла работа с отдельными Artifacts (профили таблиц, топ-90 по связности и т.п.) — пользователь **явно отменил** этот подход:
  > «...и всё сделай в виде web сайта с ссылками... Не нужны отдельные обозреватели... вообще не надо разделять таблицы исходя из кол-ва связей»
  > «и удали отдельные профили....всё должно быть единообразно»
- Стандартное правило: **не архивировать и не присылать сайт после каждой правки** — только редактировать, пересобирать, докладывать.

### 1.2. Пайплайн данных
- `parse_all_tables.py` → `all_tables_data.json` (1552 таблицы: поля, индексы, триггеры, FK, DDL).
- `parse_functions_checks.py` → `all_functions_data.json`, `all_checks_data.json`.
  - Баг: DDL-тело у всех 302 функций было пустым из-за неверного порядка тегов в regex (`<code><pre>` vs `<pre><code>`) — исправлено с fallback-паттерном.
  - Баг: утечка HTML-тегов форматирования (`<font>`, `<i>`) в текст DDL — regex расширен с `</?b>` до `<[^>]+>`.
- `all_tables_conn.json` — количество связей (исходящих/входящих/всего) на таблицу.
- `parse_procedures.py` → `all_procedures_data.json` (7902 процедуры из `Метаданные БД2\Result.html`).

### 1.3. Структура сайта (`build_site.py`, чистый Python + f-строки, без сборщиков)
- `index.html` — список всех таблиц, поиск по имени, сортировка (Название/Описание/Связей), фильтры «UX-конструкторы» / «без связей» (оба по умолчанию: UX скрыты, «без связей» показаны).
- `tables/<slug>.html` × 1552 — поля, PK/FK, индексы, триггеры, CHECK, исходящие/входящие FK, DDL по клику. «← Назад» через `window.history.back()` (возврат в то же место списка).
- `overview.html` («Схемы») — только диаграммы (Mermaid): ядро схемы (топ-22 по связности), кредитный контур, полиморфные связи, процедуры вокруг топ-10 хабов. Все узлы одного бледно-жёлтого цвета (зелёная подсветка хабов убрана), hover → узел и связанные узлы белеют, рёбра оранжевые.
- `info.html` («Инфо») — аналитика: Топ-10 таблиц по связям, **Хабы: входящие и исходящие связи** (перенесено сюда из «Схем»), полиморфные таблицы (89), UX-конструктор (125), иерархии nested-set (6) / простая самоссылка (33), файлы и журналы.
- `functions.html` — все 302 функции на одной странице (поиск по имени+описанию), DDL по клику.
- `procedures.html` + `procedures/<slug>.html` × 7902 — см. часть 3.
- Меню (закреплено, `position:sticky`): **Таблицы · Схемы · Функции · Процедуры · Инфо**. Футера нет.

### 1.4. Правки UI/UX (десятки итераций по скриншотам)
Единый моноширинный стиль названий таблиц везде (`IBM Plex Mono`, 12.5px, вес 500), заголовки колонок во всех таблицах цвета `#f2e29a`, единая высота строк (padding 9px 16px), отступы абзацев, подчёркивание активного пункта меню. Уроки: `[hidden]` проигрывает `.class{display:flex}` → добавлено глобальное `[hidden]{display:none !important}`; Mermaid встраивает свой `<style>` с `!important` → hover реализован через JS `style.setProperty(..., 'important')`; flex-контейнер (`h2`, `summary`) превращает куски текста и inline-теги в отдельные flex-элементы → оборачивать заголовок в один `<span>`.

### 1.5. Данные процедур и сверка
- `Метаданные БД2\Result.html` (109 МБ): 7902 процедуры, 712 генераторов, 39 доменов, 5 views, 7 исключений, 6 UDF (таблицы/функции там пустые).
- Процедуры сделаны как таблицы (список + отдельные страницы), а не одной страницей: DDL суммарно 34 МБ.
- Сверка с `Инфо\процедуры.mec` (7917 процедур): **21** есть в .mec, но нет в Result.html (например `AAREP_RESTRUCT_METOD`, `HP_PREPAY_CREATE`, `OKTELL_CALL_SAVE_DATA`); **6** есть на сайте, но нет в .mec (например `AAREP_REPORT_FOR_6101`, `HP_INACTIVE_CLIENTS_GET`). Экспорты сняты в разное время — не ошибка парсинга.
- Файлы таблиц в нижнем регистре: `slug()` → `.lower()` + пересборка с нуля.

## Часть 3. Работа последних сессий

### 3.1. Процедуры
- Страница процедуры: ссылки на процедуры, которые она **использует** (`EXECUTE PROCEDURE x` и `FROM x(...)` в DDL), и процедуры, из которых она **вызывается** (обратный граф), оба блока сворачиваемые, карточки в одну строку без переноса; затем параметры; затем DDL. Блок «Вызывается из других процедур».
- Сворачиваемые «Входные/Выходные параметры» (`<details>`, стрелка в заголовке).
- Кнопки «Копировать» (таблицы/процедуры — в строке «Показать DDL»; функции — только когда код раскрыт) и «Показать код ⇄ Скрыть код».
- Режим **«По категориям»** на `procedures.html`: переключатель «Список / По категориям»; в режиме категорий фильтр и счётчик скрыты. Категории по префиксу имени: список пользователя (UXP$, AAREP, BLANK, CARD, CB24, CB_, CC_, CES_+CEO_, CHECK_, CM_, CIB_, CRM_, ELCARD_, EPASS_, FIND_, FM_, FSROBOT_, GET_, HP_, FT_, HR_, INN_, INSERT_, IPC_, IPF_, ISHENIM_, KIB_, KIBSEND_, KONTRACT_, MC_, MILLICARD_, MKR_, MONETA_, OKT_, PKB_, PRINT_) + найденные дополнительно (≥5 процедур): EQUIFAX_, CRIF_, RCIB_, SVC_, ANTIFRAUD_, EDOC_, LLC_, OKTELL_, PAYSYS_, AGREEMENT_, CLIENTSTATUS_, CNP_; последняя категория «Другие» (309 процедур; категоризировано 7593). Внутри каждой категории — свои сортируемые заголовки (Название / Описание / Входных параметров), по умолчанию по названию. Пользователь написал «таблицы», но префиксы относятся к процедурам — реализовано для процедур.
- Колонка «Входных параметров» всё ещё показывает **сумму** входных+выходных (меняли только заголовок; на это указано пользователю).

### 3.2. Автономность сайта (закрытый контур)
Сайт должен работать без интернета: `mermaid.min.js` v10.9.1 и 19 шрифтов `.woff2` (Source Serif 4, Public Sans, IBM Plex Mono) скачаны в `vendor/` и при каждой сборке копируются `build_site.py` в `site/assets/` (+ локальный `fonts/fonts.css` вместо Google Fonts `@import`). Внешних зависимостей не осталось.
